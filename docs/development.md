# Vývoj a kontroly

## Stav

Repozitář obsahuje specifikace, vývojové nástroje a průběžnou verzi 0.1 hry; aktuální stav milníků shrnuje [roadmapa](roadmap.md). Produkční build obsahuje volitelnou instalovatelnou PWA a úplný offline balík ([D-031](decisions/031-installable-offline-pwa.md)). Úspěch lokálního CI nenahrazuje akceptaci hry ani fyzická zařízení.

Výsledky prvního lokálního ověření včetně red/green a negativních kontrol jsou v [protokolu z 2026-10-09](validation/2026-10-09-toolchain.md); průběžné ověření verze 0.1 je v [protokolu v0.1](validation/2026-10-09-v0.1.md).

První konkrétní vývojový řez a jeho pořadí jsou připravené v [zahájení M0](development-start.md).

## Prostředí

Používáme projektové verze **Node 24.21.0 a npm 11.19.0** přes již nainstalovanou Voltu. Nový spolupracovník nejprve nainstaluje [Voltu podle oficiálního návodu](https://docs.volta.sh/guide/getting-started). `volta` v `package.json` je zdroj projektových verzí; `engines` a `.npmrc` odmítnou instalaci nesprávným runtime. `packageManager` zaznamenává verzi npm pro další nástroje. Při upgradu udržuj tyto údaje shodné.

```bash
volta fetch node@24.21.0 npm@11.19.0
volta run node --version
volta run npm --version
volta run npm ci
volta run npm run check
```

Příkazy spouštěj v kořeni repozitáře. Volta vybírá verze podle projektu a sdílí jejich cache; neměníme její globální výchozí verze. Explicitní `volta run` je spolehlivý i v shellu zděděném z nástroje spuštěného pod jinou Node verzí. Pro delší práci lze otevřít `volta run bash`; příkazy `npm` a `git commit` pak spouštěj uvnitř tohoto shellu. Alternativně prefixuj jednotlivé příkazy z tabulky pomocí `volta run`, včetně `volta run git commit`. CI má správný runtime přímo přes setup-node a Voltu nepotřebuje.

Bez Volty (například v jednorázovém cloudovém kontejneru) lze použít oficiální archiv `node-v24.21.0-<platforma>.tar.xz`. Nejdřív jej ověř proti `SHASUMS256.txt` ze stejného vydání, rozbal mimo repozitář a jeho `bin/` přidej na začátek `PATH` jen pro danou relaci. Globální runtime se nemění.

Samotné závislosti jsou oddělené v `node_modules/`, nejsou instalované globálně. Toto je izolace verzí a závislostí, nikoli bezpečnostní sandbox. Python virtualenv ani Docker nejsou pro tento Node projekt potřeba.

Obnova prostředí je znovu `npm ci`: nahradí `node_modules/` podle commitnutého `package-lock.json` a obnoví hook přes `prepare`. Lockfile nemaž kvůli běžné reinstalaci. `.idea/`, `.jbeval/`, výstupy a lokální `.env` se necommitují. Nové závislosti instaluj s přesnou verzí a dokumentuj jejich účel.

## TypeScript projekty

Společná strict pravidla jsou v `tsconfig.base.json`. Kořenový `tsconfig.json` kontroluje Node skripty, testy a konfigurace bez DOM typů. `src/tsconfig.json` kontroluje webovou aplikaci s DOM typy a rozlišením modulů pro Vite; má `skipLibCheck`, protože deklarace Phaseru 4.2.1 samy neprojdou strict kontrolou TypeScriptu 6 (TS2526, TS2416, viz [D-004](decisions/004-renderer-and-phaser.md)). `tests/e2e/tsconfig.json` kontroluje Playwright testy a jejich konfiguraci s DOM typy pro kód v `page.evaluate`; kořenový projekt je vynechává. `src/domain/tsconfig.json` kontroluje čistou zónu bez DOM a Node typů. `src/service-worker/tsconfig.json` kontroluje service worker s typy `WebWorker` bez DOM; webový projekt ho vynechává. `npm run typecheck` spouští všech pět projektů. Konfigurace se jmenují `tsconfig.json`, protože typově informovaný ESLint (`projectService`) hledá nejbližší soubor právě tohoto jména. Relativní importy v `src/` uvádějí příponu `.ts`, aby je stejně načetly testy v Node.

TDD: napiš test pozorovatelného chování → spusť a ověř správný důvod selhání → minimální implementace → zelený test → refaktoring → `npm run check`. Chyba instalace/importu není red. Výsledek a provedené příkazy uveď v předání. Nové testy čisté logiky patří do `tests/**/*.test.ts`. Testy kreslení, které potřebují typy Phaseru, patří do `src/render/**/*.test.ts`: kontroluje je rendererový TypeScript projekt a Vitest je pouští v Node s náhradou jen kreslicí platformy (například `volta run npm test -- src/render/TunnelView.test.ts`); do produkčního bundlu se nedostanou, protože je nic neimportuje. `.only`, skip ani vyšší retries nesmějí zakrýt regresi.

## Hranice čisté domény

`src/domain/**` a `src/config/**` tvoří čistou zónu bez Phaseru, DOM, úložiště, audia, hodin a náhodnosti. Vynucuje ji ESLint (`eslint.config.mjs`):

- Lokální pravidlo `vlacek/pure-imports` (`tools/eslint/pure-imports.mjs`) povolí jen relativní importy, které zůstanou uvnitř čisté zóny. Odmítne balíčky (`phaser`), aliasy (`@/…`), cesty do `render/`, `ui/`, `platform/`, `app/`, re-exporty, dynamický a vypočtený `import()`, `import('x').Typ`, `require` a importy s `?query`. Protože totéž platí pro každý čistý soubor, nevede ven ani řetězec re-exportů.
- `no-restricted-globals` (včetně `globalThis`), `no-restricted-properties` a `no-restricted-syntax` zakazují `window`, `document`, `localStorage`, `performance`, časovače, `Math.random()`, `Date.now()`, `new Date()`, `import.meta` a `declare global`. `triple-slash-reference` zakazuje `/// <reference lib="dom" />`.

Mimo čistou zónu platí ještě `no-restricted-imports`: `phaser` smí importovat jen `src/render/**`.

Čas, náhodnost (seed) a platformní data předává doméně volající. Negativní testy v `tests/tooling/domain-boundaries.test.ts` lintují skutečnou projektovou konfigurací ukázky každého zakázaného vzoru v obou adresářích zóny. Kontrolní testy ověřují povolený import uvnitř zóny a neomezený platformní kód. Druhou pojistkou je TypeScript projekt `src/domain/tsconfig.json` (lib ES2024, `types: []`), který kontroluje `src/domain` i `src/config` bez DOM a Node typů. Pre-commit typecheck nespouští, proto lint zůstává hlavní okamžitou kontrolou.

## Browserové testy

Playwright je připnutý v `package.json` a stahuje vlastní Chromium odpovídající verzi (pro 1.64.0 revize 1248, Chromium 156). Konfigurace je `tests/e2e/playwright.config.ts`; testy se jmenují `*.spec.ts`, takže je Vitest nespouští. `npm run test:e2e` nejdřív vytvoří produkční build a server spustí Playwright sám. Výstupy jsou v `test-results/` a v CI v `playwright-report/`; obojí je ignorované Gitem.

```bash
volta run npx playwright install chromium
volta run npm run test:e2e
```

Pokud prostředí nastavuje `PLAYWRIGHT_BROWSERS_PATH` na adresář se starší revizí prohlížeče (například předinstalovaný kontejner), nainstaluj správnou revizi jinam a stejnou cestu předej i testům, např. `PLAYWRIGHT_BROWSERS_PATH=$HOME/.cache/ms-playwright`. Spouštění se starším Chromiem přes `executablePath` není podporovaná konfigurace. Testy mají `forbidOnly` a žádné retries; dotykový projekt používá `hasTouch`. Emulace není test fyzického zařízení.

Měření plynulosti ([D-034](decisions/034-ride-frame-pacing-instrumentation.md)): `flock /tmp/vlacek-playwright.lock env PERF_SECONDS=60 volta run npm run measure:perf` měří nejdelší vlak, seed 20261009, bez snapshot pollingu v okně; pořadí intervalů zůstává v JSON. Pro CPU ×4 přidej `PERF_CPU_RATE=4`, pro CDP trace s GC `PERF_TRACE=1`; lze je kombinovat, například `flock /tmp/vlacek-playwright.lock env PERF_SECONDS=60 PERF_CPU_RATE=4 PERF_TRACE=1 volta run npm run measure:perf -- --output=/absolutni/cesta/run-N`. Výstup obsahuje medián/p95/worst, počty >1,5× medián okna / >50 / >100 ms a medián mezery mezi dlouhými snímky. `samplingWindow` exportuje start/end v hodinách stránky i trace a renderer pid/tid; `gc` počítá jen MinorGC/MajorGC na ověřeném `CrRendererMain` měřené stránky oříznuté na okno, `workerGc` zvlášť. Pro srovnání základ/head opakuj každý profil alespoň třikrát bez jiné zátěže. Desktop headless s CDP throttle není měření fyzického tabletu.

Celá uživatelská cesta (`tests/e2e/game.spec.ts`) čte stav přes diagnostické API `window.__vlacek.snapshot()`, které zapne `?debug=1` nebo Diagnostika ve skrytých vývojářských volbách ([D-020](decisions/020-developer-menu.md)). Volby se v pauze otevřou pěti aktivacemi řádky Build během 3 s (myš, dotyk, Enter i mezerník). Diagnostika, renderer a seed mají prioritu adresa → `vlacek.dev.v1` → výchozí hodnota; kvalita adresa → `settings.quality` → Auto. `?quality=auto|standard|low` platí jen pro dané načtení; `renderProfile` ve snapshotu uvádí efektivní kvalitu, `maxDpr`, `fpsLimit` a efekty. Použití i návrat na výchozí volby nejprve uloží cestu a nastavení přes `interrupt()`, potom změní dev klíč a načtou stránku bez čtyř dev parametrů; při neúspěšném uložení se stránka znovu nenačte a hodnoty zůstanou v panelu. Otevírací sekvence v `dev-menu.spec.ts` drží hodiny `page.clock` jen během pěti aktivací. Zapnutý HUD je při jízdě nejvýše dvouřádkový a propouští dotyky do světa; při pauze se skryje. „Diagnostika – podrobnosti“ v dev menu ukáže vzorek z okamžiku otevření v českých skupinách a „Kopírovat JSON“ kopíruje nezkrácený snapshot, se selektovatelným textem při chybějící či zamítnuté Clipboard API. `window.__vlacek.snapshot()` a jeho kontrakt zůstávají beze změny. Menu samostatně ukazuje skutečný seed rozehrané cesty s kopírováním a oběma restarty; nejprve `interrupt()` vyžaduje `saved`, potom se primárně uloží nová cesta se stejnou soupravou a počáteční polohou/tickem 0. Teprve po úspěchu se vymění živá cesta, odstraní dev parametry a vrátí pauza. Restart nemění dev klíč, neprovádí reload a nepoužije rozpracovaná pole. Při selhání kteréhokoli zápisu původní cesta zůstane a panel uvede příčinu; nový save používá stávající formát. `tests/unit/ui/diagnosticsFormat.test.ts`, `tests/integration/seedRestart.test.ts` a rozšířený `tests/e2e/dev-menu.spec.ts` pokrývají formátování, skupiny, oba restarty, jejich selhání, schránku i průchod držení přes HUD na 568 × 320, 844 × 390, 1140 × 512 a 1280 × 800. `AudioManager.stopAll()` je kontrakt i pro budoucí nahrané zvuky: synchronně zastaví a odpojí všechny aktivní zdroje a uvolní jejich hlasový rozpočet právě jednou, bez odemčení či obnovení AudioContextu; volá se jen po úspěšném restartu a zvuk pak čeká na gesto pokračování. Chybu světa reprodukuj otevřením `?debug=1&seed=N` se seedem z pauzy nebo ze snapshotu a stejným buildem ([D-007](decisions/007-world-seed-in-url.md)). Vícedotykové testy posílají `Input.dispatchTouchEvent` přes CDP: `touchEnd` uvolní právě uvedené prsty. Časy gest se předávají explicitním `timestamp`, protože automatizační kanál doručuje události se zpožděním až stovek milisekund. Test `tests/e2e/render.spec.ts` porovnává stejný stojící snímek z WebGL a Canvas a hlídá chyby kreslení, které se projeví jen v jednom rendereru ([D-010](decisions/010-webgl-single-texture-batches.md)). Měření `*.perf.ts` má vlastní konfiguraci `tests/e2e/perf.config.ts` a běží jen přes `npm run measure:perf`. Sestavu měření skládá `tests/e2e/perfConsist.ts`; unit test `tests/tooling/perf-consist.test.ts` ověřuje výchozí smíšenou soupravu přesně 2 000 u se `steam_local`, opakování `PERF_WAGON` do délkového limitu a odmítnutí neznámého ID. Měření zaznamenává také `medianFrameMs`. Nejdelší soupravu z největších vozidel změří `PERF_LOCOMOTIVE=steam_express PERF_WAGON=cargo_cars PERF_SECONDS=30 volta run npm run measure:perf` (`cargo_cars` je nejdelší druh vagonku, 204 u). Atlasovou diagnostiku a regresní příkazy popisuje [sekce regionálních atlasů](#regionální-a-sezónní-atlasy). `tests/e2e/picker.spec.ts` hlídá, že depo při změně lokomotivy a úpravách návrhu znovu používá DOM karet a jejich SVG vrstvy, včetně uvolnění při odchodu a opětovného vstupu. Diagnostika `oncoming.trains[].locomotiveId` uvádí skutečnou lokomotivu protijedoucího vlaku; `horns.spec.ts` ověřuje přesný tón této identity. Pixelový test oblohy kontroluje původní rozsah nad vlakem v obou rendererech a jeho pozitivní kontrola musí zachytit vloženou čáru ve všech 844 sloupcích. Diagnostika `scenery.secondaryTrackViews` počítá skutečně vytvořené chunky souběžné koleje a `scenery.secondaryPortalViews` jejich portálové kopce, s atlasem i bez něj (R7). Diagnostika `backdrop` hlásí skutečný stav vrstev pozadí: `currentBiome`, `incomingBiome` a průběh prolínání `fade` od 0 do 1; `scenery.biome` je cílový biom krajiny před vlakem. Test R10 je čte v prvním vykresleném snímku nové cesty. Snapshot obsahuje kumulativní `rideFramesDrawn` za život renderové scény. Počítá dokončené kreslicí aktualizace viditelné jízdy: pod neprůhlednou obrazovkou nebo výzvou k otočení neroste, v průsvitné pauze roste dál ([D-006](decisions/006-runtime-architecture.md)). Není potvrzením GPU renderu; neprůhlednou clonu mezi canvasem a UI vlastní `AppController` a odstraní ji až po události `Phaser.Renderer.Events.POST_RENDER` vracejícího se světa, i ve 30 FPS profilu a po ztrátě kontextu WebGL. `frameSamples` udává naplnění klouzavého statistického bufferu, nikoli celkový počet snímků, a neslouží k synchronizaci testů. `ride-visibility.spec.ts` a `ride-reveal.spec.ts` sledují každý browserový snímek při odchodu do depa, Vyjet, Pokračovat, návratu z depa a odstranění výzvy k otočení ve standardním i nízkém profilu, zachování rozpracovaného prolínání biomů při návratu ke stejné cestě a ztrátu kontextu WebGL. Stejné pozorování platí pro otevřený vývojářský panel: pod ním `rideFramesDrawn` neroste ani po otočení a po zavření, i po neúspěšném použití voleb, se průsvitná pauza odkryje až po novém renderu světa.

Tunely ([D-018](decisions/018-bridges-and-tunnels.md)): `tunnels[].train` a `RideScene.stats.tunnels[].train` rozlišují `outside`, `partly`, `inside` vůči zakrytému středu tunelu; otevřená ústí nejsou plné zakrytí. `vehicles` uvádí stejný stav pro každé hráčovo vozidlo, `alpha` je vždy 1. `bubbles` ve snapshotu obsahuje pouze odkryté bubliny podle stejného `TunnelView.coversPoint`, který filtruje hit-test i prasknutí. Regrese `tunnel-occlusion.spec.ts` porovnává pixely stejného zmrazeného snímku s vozidly/částicemi a bez nich, s pozitivní kontrolou odkryté části téhož částečně zakrytého vozidla v obou ústích a uvnitř otevřeného ústí NPC portálu. Statické pixely portálu se nemění přes vznik a odstranění NPC při stejné poloze hráče, renderovém ticku a kameře; kryty uvolní až vlastník scenérie. Brzdění postupuje přes skutečné snímky efektů.

Dlouhé tunely a velké mosty doplňuje [D-026](decisions/026-long-tunnels-and-bridges.md): úplný rozsah tunelu sdílejí fragmenty napříč chunky, portály sledují místní tečnu koleje a fragment zaniká s chunkem. `RockTunnelView` skládá pás skalního materiálu přes `atlasFramePixels(frameTexture(...))` před `immutableTexture`; každý readback uvolňuje v `finally`. Nevzniká další scratch canvas ani trvalá CPU kopie na WebGL. Silueta hory, vegetace, vnitřek a závěsy jsou statické vektory. Viadukty a ocelové mosty zachovávají vodní koridor mezi podpěrami i elektrické vedení. Regrese: `VITEST_MAX_WORKERS=4 volta run npm test -- src/render/TunnelView.test.ts src/render/RockTunnelView.test.ts tests/unit/world/Structures.test.ts`; browserové pixely a průjezd: `flock /tmp/vlacek-playwright.lock volta run npm run test:e2e -- tests/e2e/long-structures.spec.ts tests/e2e/tunnel-occlusion.spec.ts --workers=2`.

Přejezdy ([D-021](decisions/021-crossing-closes-in-view.md)): `crossings[].worldX` je střed přejezdu ve světových u, `screenX` jeho projekce v CSS px i mimo viewport a `tailX` konec hráčovy soupravy ve světových u. Projekce vychází z pevného simulačního kroku; interpolovaná kresba se může lišit nejvýš o jeden pohybový krok. Crossing E2E pozorují každý browserový snímek. Regrese fronty začíná platným save se stojícím vlakem na přejezdu, zachytí existující konečný `crossedBefore` a přes veřejný klávesový vstup zabrzdí hned po uvolnění rozšířené zóny posledním vagónem. Úspěch vyžaduje stojící vlak, stále existující otevřený přejezd se závorami nahoře, vlak mimo silnici a `crossed > crossedBefore`; odstraněná instance nepředstírá dokončený průjezd. Renderový test `src/render/crossingViewWiring.test.ts` ověřuje skutečné kreslení `ChunkView` v art i fallback cestě na rovině a obou sklonech.

Diagnostika překryvu výstražníků používá pro jeřáb `paintedBoundsU`: konzervativní kreslenou oblast těla a dvě oddělené oblasti podvozků overlaye. Průhledný spodní okraj rámu ani mezera mezi podvozky už nehlásí falešný překryv. Výpočet zahrnuje atlasový okraj, pivot, rotaci a transformaci rodiče; kola dál používají kruh. Kresba ani přejezd se neposouvají a neořezávají. Změna SVG vyžaduje přezkoumání metadat ([D-025](decisions/025-farm-forest-content.md)).

## Kontrola dokumentace

Validátor rozpozná Markdown odkazy a obrázky, relativní cesty vůči zdrojovému dokumentu a `/cesty` vůči kořeni repozitáře. Odstraní query/fragment a dekóduje URL cestu. Existující soubor i adresář je platný cíl. Chybějící cíl nebo neplatné URL kódování způsobí nenulový exit s názvem zdrojového souboru a cílem.

Externí URL, protocol-relative URL, čisté `#fragmenty` a code bloky se ignorují. Kontrola neověřuje vzdálené servery, existenci nadpisových kotev ani odkazy v raw HTML. Přejmenování či smazání cíle zachytí úplné `npm run check:docs`, i když zdroj odkazu zůstal beze změny. Nové návody musí mít odkaz z README nebo příslušného existujícího návodu.

## Git hook a CI

`npm ci` spustí Husky `prepare`. Pre-commit ověřuje `git diff --cached --check`, poté lint a formát staged souborů; při změně Markdownu také místní odkazy. Kontroly neopravují soubory ani nepřidávají cizí změny do indexu. lint-staged dočasně skryje unstaged změny a obnoví je po kontrole. Při selhání oprav konkrétní problém, explicitně stage opravu a opakuj commit.

Pre-commit na každém staged souboru spouští secretlint (`--no-glob`, cesty se berou doslova) a limit velikosti. Nepouští síťové požadavky, plný typecheck ani celou testovací sadu. Samotné odstranění souboru nemusí vyvolat lint-staged úlohu; proto je před commitem povinné `npm run check` a stejná kontrola běží v CI. Testy v `tests/tooling/pre-commit.test.ts` v dočasném repozitáři ověřují, že hook odmítne staged privátní klíč i příliš velký soubor. Kontrola tajných údajů je ochrana proti omylu, nikoli záruka: neodhalí každý formát tajemství.

Workflow `.github/workflows/ci.yml` běží na push, pull request a ruční spuštění. Job **Quality checks** má read-only oprávnění, timeout 10 minut a action reference připnuté na commit SHA. Starší běh pro stejný ref se ruší, kromě běhu na `master`, aby se nepřerušilo nasazení. setup-node čte Node verzi z `package.json`; `.npmrc` při `npm ci` ověří i přesnou npm verzi dodanou s připnutým Node. CI vynechává instalaci lokálních hooků pomocí `HUSKY=0`, spouští `npm run check`, produkční `npm run build` a `npm run report:budgets`. Job **E2E** běží v šestnácti paralelních shardech (`E2E (1/16)` až `E2E (16/16)`, každý s timeoutem 15 minut a jedním prohlížečem): nainstaluje Chromium přes `npx playwright install --with-deps chromium`, spustí `npm run test:e2e -- --shard=N/16` a při selhání nahraje report jako artefakt `playwright-report-N` na 7 dní. Playwright dělí plně paralelní testy rovnoměrně. Celá sada V1 se do jednoho 15minutového jobu nevejde (na GitHub runneru 195 testů za 14 minut). Při dvou shardech trvala polovina sady 12,5 minuty, takže pomalé zrcadlo balíčků Ubuntu při instalaci Chromia (jednou 10 minut) shard zrušilo. Se specy světa v2 trvala čtvrtina sady přes 15 minut (běh 38568400187), proto bylo shardů osm. Dva prohlížeče se softwarovým WebGL na čtyřech vCPU runneru ale zdržovaly publikaci atlasů D-030 tak, že testy s více publikacemi přetáhly 30 s, ačkoli samostatně procházejí (běhy 38915343324 a 38920234409). Proto má CI `workers: 1` (`tests/e2e/playwright.config.ts`) a šestnáct shardů; lokální `--workers=2` platí dál. Timeout jobu ani testů se nezvyšuje.

GitHub workflow už běží po pushi; první úspěšný běh je zaznamenaný v [protokolu](validation/2026-10-09-toolchain.md). V nastavení ochrany větve nastav **Quality checks** a **E2E** jako povinné kontroly před mergem; samotný YAML toto nastavení nevynutí. Při ověření 2026-10-09 byla větev `master` nechráněná. Lokální průchod není důkaz úspěšného GitHub běhu. Fyzická zařízení se v CI netestují.

## Nasazení na GitHub Pages

Job **Deploy to GitHub Pages** běží jen pro push nebo ruční spuštění na `master` a až po úspěšných jobech **Quality checks** a **E2E**. Jen tento job má oprávnění `pages: write` a `id-token: write`. Po čisté instalaci zjistí `actions/configure-pages` cestu webu (`/vlacek`), build ji dostane přes `VLACEK_BASE` a `actions/upload-pages-artifact` + `actions/deploy-pages` nahrají obsah `dist/`. Do repozitáře se žádný build necommituje. Po nasazení job nainstaluje Chromium a spustí `smoke.spec.ts` proti skutečné adrese (`E2E_BASE_URL`); test čeká, až CDN vrací `<meta name="vlacek-build">` s commitem běhu (`E2E_EXPECT_COMMIT`), a ověří start rendereru bez externích požadavků. Smoke test čeká na očekávaný commit přes přímý HTTP požadavek před otevřením řízené karty, aby starý aktivní worker nepřipnul staré HTML během čekání na CDN. Součástí `smoke.spec.ts` je i kontrola úplného aktivního balíku a offline reload po prvním online načtení. Lokální preview není důkaz provedeného deploy jobu ani instalace na zařízení.

V nastavení repozitáře musí být **Settings → Pages → Source: GitHub Actions**. Prostředí `github-pages` standardně povoluje nasazení jen z výchozí větve; pracovní větve proto web nemění. Adresa je <https://pavelpancocha.github.io/vlacek/>. Nasazený obsah ověř podle `<meta name="vlacek-build">`, který musí odpovídat commitu běhu. Workflow ověř lokálně pomocí actionlint podle [protokolu nástrojů](validation/2026-10-09-toolchain.md); ověření nasazení je v [protokolu zástupné stránky](validation/2026-10-09-pages-skeleton.md). Volbu popisuje [rozhodnutí D-002](decisions/002-github-pages.md).

## Reprodukce nahraných zvuků

Audio používá FFmpeg **6.1.1-3ubuntu5** / libmp3lame, mono MP3 44 100 Hz VBR q=5. Není nová npm závislost. FFmpeg musí být v PATH (`ffmpeg -version`); na Ubuntu 24.04 odpovídá použitý balík verzi `7:6.1.1-3ubuntu5` (`sudo apt-get install ffmpeg=7:6.1.1-3ubuntu5`). Na jiných systémech použij FFmpeg 6.1.1 s libmp3lame z [oficiálního rozcestníku](https://ffmpeg.org/download.html). Nová instalace na čistém stroji NEOVĚŘENO; lokální export použil již nainstalovanou verzi. Úplné zdrojové nahrávky nepatří do Gitu. Ze [sources.json](../scripts/audio/sources.json) stáhni každou unikátní adresu `download` pod jménem `original`; SHA-256 musí přesně souhlasit. HTTP 403 ze zdrojového CDN je překážka reprodukce, nikoli důvod měnit nahrávku bez nového ověření licence a hashe. Podrobnosti v [D-022](decisions/022-recorded-sounds.md).

```bash
volta run node scripts/audio/process-audio.ts /cesta/k/originalum
volta run node scripts/audio/credits.ts
volta run node scripts/audio/verify-audio.ts
volta run node scripts/audio/contact-sheet.ts /cesta/k/vystupu
VITEST_MAX_WORKERS=4 volta run npm test -- tests/unit/content/soundManifest.test.ts tests/unit/platform/AudioManager.test.ts tests/unit/platform/AudioDirector.test.ts tests/unit/platform/VoiceBudget.test.ts
flock /tmp/vlacek-playwright.lock volta run npm run test:e2e -- tests/e2e/horns.spec.ts tests/e2e/recorded-audio.spec.ts --workers=2
```

`process-audio` ověří originály, vytvoří a odstraní dočasný normalizovaný PCM WAV, trimuje po vzorcích, provede jemné fades/crossfades, EQ a normalizaci a exportuje MP3. `verify-audio` ověří dekódované délky, smyčkové body, špičky, spoje a rozpočet 3 MiB; FFmpeg není potřebný pro běžný webový build ani unit testy. CI `npm run check` kontroluje manifest, soubory a provenienci unit testy, numerický audio audit se provádí při exportu. Export obnoví také `assets/audio/credits.txt`. Samostatný příkaz `credits.ts` obnoví pouze kredity z téže provenience bez FFmpeg a originálů. Unit kontrola vyžaduje přesnou shodu textu s generátorem a úplný kredit každé CC BY nahrávky. Vite dodá fingerprintovaný text do buildu; odkaz O zvucích — autoři a licence v sekci Zvuky je dostupný i na publikovaném webu. E2E ověřuje text z produkčního serveru. Kontaktní list obsahuje waveform a spektrogram každého souboru. Číselné a obrazové kontroly nenahrazují poslech. Fyzický Android/Tesla, Firefox a Safari jsou **NEOVĚŘENO**.

`AudioManager` před prvním gestem nic nestahuje ani nezakládá `AudioContext`; PWA precache ale po prvním snímku stáhne MP3 soubory na pozadí spolu se zbytkem buildu pro offline hraní, i při vypnutých zvucích ([D-022](decisions/022-recorded-sounds.md), [D-031](decisions/031-installable-offline-pwa.md)). S vypnutými zvuky `AudioManager` nezačíná fetch/decode; již zahájené dekódování nelze přerušit, ale jeho výsledek po ztlumení nic nepřehraje. Selhání v `audioDetails.failures` neruší hru; nepovedený soubor se během návštěvy neopakuje. Znovunačtení stránky dovolí nový pokus. Každý klíč vrstvy má nejvýše jednu čekající operaci; další framy přepisují jen poslední požadovaný stav. Dispose abortuje vlastněné fetch požadavky a zabrání pozdnímu playbacku i cache; probíhající decode nelze přerušit. `audioDetails.pendingLayers` ukazuje počet čekajících operací. Zvířecí reakce, pop a dřevěné ťuknutí se po 250 ms zahodí; buffer zůstane pro další čerstvý požadavek. Píšťaly a explicitní vývojářský poslech tuto lhůtu nemají, pauza/přerušení je však stále invalidují. Pauza/skrytí vždy suspendují kontext, pokračování vyžaduje gesto. Vývojářský seznam Zvuky dovolí explicitní poslech v pauze; přepnutí ukázky zastaví předchozí bez suspendování kontextu, Zastavit/Zavřít jej ukončí.

Diagnostika audia: `active` počítá přijaté hlasové sloty. `sourceCount` počítá všechny stále vlastněné source uzly včetně doznívání a parních rázů; `retiringSources` a `retiring` ukazují dohasínající zdroje podle původního klíče. Strop je 10 zdrojů bez pulzní páry / 11 se dvěma rázy, nejvýše 2 tail zdroje. Jeden dekódovaný one-shot s prioritou nad slabší obětí může čekat na 10ms uvolnění tailu a událost `ended`; zachová epochu a původní absolutní termín 250 ms pro zvířata. `stopAll`/`suspend`/mute/`dispose` čekání zruší. Regrese jsou v `tests/unit/platform/AudioManager.test.ts`.

## PWA a offline na preview

`volta run npm run build` vytvoří manifest, kredity, `precache.json` a `sw.js`. Vite plugin `scripts/pwa/plugin.ts` sestaví inventář ze skutečného `dist/` včetně emitovaných SVG/PNG, všech MP3, JS/CSS, HTML a ikon. Každý soubor má SHA-256; identita balíku zahrnuje build ID, base, soubory a zdroj workeru. Zdroj workeru má vlastní strict WebWorker projekt `src/service-worker/tsconfig.json`, který je součástí `npm run typecheck`. Nepřidává se závislost. ESLint vynechává generované `test-results/` a `playwright-report/`; nejde o zdrojový kód.

Offline testuj na localhostu nebo HTTPS, nad produkčním buildem:

```bash
volta run npm ci --prefer-offline
VLACEK_BASE=/vlacek/ volta run npm run build
VLACEK_BASE=/vlacek/ volta run npm run preview -- --port 4201 --strictPort
```

Otevři `http://localhost:4201/vlacek/` online. Vyjeď, v pauze pětkrát během 3 s aktivuj Build a v „Aplikace a offline“ počkej na „offline připraveno“ s ID balíku. V browserových DevTools přepni Network na Offline a obnov stránku: musí fungovat výběr mašinky, depo, jízda i uložené audio. Vypnutí samotné HTTP cache nenahrazuje vypnutí sítě. `dev` worker neregistruje; LAN HTTP z jiného zařízení není bezpečný localhost tohoto zařízení.

Připravovaná nová verze nevyvolá reload. Zavři všechna okna/karty této hry a znovu ji otevři, aby se čekající worker aktivoval. První aktivace záměrně nepřebírá již otevřenou kartu; následující načtení už obslouží worker. Starý worker nepoužije HTML jiného buildu. Cache zachovává aktuální a jednu předchozí úplnou verzi. Pokud se vydání změní mezi HTML a registrací, ID cache se ukáže, ale odlišný build neoznačí starou stránku za offline připravenou.

Pro čistý test v DevTools → Application → Service Workers zvol u registrace tohoto scope **Unregister**, v Cache Storage smaž jen cache s prefixem `vlacek:/vlacek/:` (pro root `vlacek:/:`) a zavři všechny jeho karty. Pak začni novou online návštěvou. Nemaž místní úložiště, pokud chceš zachovat save; nepoužívej plošné „Clear site data“ jako běžný reset workeru. Při změně base/portu si ověř správný origin a scope. Vymazání cache za běhu se po návratu stránky projeví jako „offline není dostupné“.

Automatické ověření v prostředí se sdílenými lane:

```bash
VITEST_MAX_WORKERS=4 volta run npm test -- tests/unit/pwa tests/unit/platform/SaveRepository.test.ts
flock /tmp/vlacek-playwright.lock volta run npm run test:e2e -- tests/e2e/pwa.spec.ts tests/e2e/smoke.spec.ts --workers=2
```

E2E používá produkční build a existující Playwright preview na portu 4173. Aktualizační fixture obsluhuje reálné soubory buildu a mění identitu HTML/JS; nevydává nic na Pages. Headless Chromium neprokazuje skutečnou instalaci OS. Instalace a offline na fyzickém Androidu, iOS a Tesle jsou **NEOVĚŘENO**.

Při rollbacku se již úplná cache téhož vydání znovu použije po kontrole všech hashů; selhání reinstalace nesmaže aktivní ani čekající balík. Regrese A → B → rollback A a úklid A → B → C pokrývá `tests/e2e/pwa.spec.ts`.

### Start a výkon jízdy

`?debug=1` nebo diagnostika v dev menu po znovunačtení zpřístupní `window.__vlacek.snapshot().perf`; podrobnosti mají českou skupinu Načítání a Kopírovat JSON celý vzorek. Sonda měří navigaci → interaktivní úvod, Pokračovat/Vyjet → první prezentovaný snímek a dostupnou grafiku, skutečně dekódované SVG a jejich Resource Timing fetchy, CPU fáze atlasů, generování/pečení prvních 12 chunků a dlouhé úlohy >50 ms za prvních 15 s RIDING. Souběžné decode intervaly se sčítají; nejsou čistým CPU časem ani délkou startu. Upload je synchronní odeslání na CPU, nikoli GPU; geometrie simulační LUT se neměří. Bez diagnostiky se sonda nevytváří, observátor a posluchače se uvolňují s vlastníkem ([D-032](decisions/032-startup-and-ride-performance.md)).

Timing používá existující `AtlasMetrics`, neobaluje texture manager a neúčtuje čekání mezi yieldy. Nezměněný request nečte timing hodiny; nové obsahové okno ve stejném měřítku se měří. Počet sestavení roste až po úspěšné publikaci. Start dekóduje první okno (integrační vzorek 222 SVG místo původních 422); starší benchmarky v D-032 zůstávají historickými vzorky. Pravidelný HUD každých 250 ms čte jen osm levných údajů, plný geometrický snapshot vzniká až na požádání. CPU ×4 a SwiftShader jsou relativní emulace; FPS zisk ani start na fyzickém tabletu/Tesle tím nejsou prokázané.

### Prostředí a nástroje

- `EBADENGINE`: ověř `volta run node --version`, `volta run npm --version`, kořen projektu a Volta shims v PATH. Při zděděném jiném runtime použij explicitní `volta run npm ci`. Nepřepisuj `engine-strict` jen kvůli obejití chyby.
- Nesoulad lockfilu: při záměrné změně závislosti aktualizuj manifest i lockfile, pak ověř čisté `npm ci`.
- Síťový timeout instalace: ověř dostupnost npm registry. Pro IPv4 preferenci lze jednorázově použít `NODE_OPTIONS=--dns-result-order=ipv4first volta run npm ci`; není to požadavek projektu ani vypnutí TLS. Opakovaný pokus využije cache. Ručně stažený Node archiv vždy ověř proti oficiálnímu `SHASUMS256.txt`, než jej předáš Volta cache.
- Chyba formátování: spusť `npm run format`, prohlédni diff a znovu spusť kontrolu.
- Neplatný odkaz: oprav cestu vůči zdrojovému dokumentu; nevypínej validátor.
- Prázdná stránka nebo 404 po nasazení do podadresáře: ověř, že `dist/index.html` odkazuje na assety s prefixem `VLACEK_BASE`, v deploy jobu výstup `base_path` z `actions/configure-pages` a lokálně stejné `VLACEK_BASE` pro build i preview. Vite běží s `appType: 'mpa'`, takže chybná cesta skončí 404 místo tichého vrácení `index.html` (PWA-10).
- Pages zobrazují README místo hry: v nastavení Pages je zdroj „Deploy from a branch“; přepni jej na „GitHub Actions“.

Každá nová funkce a tooling musí podle AGENTS.md upravit relevantní dokumentaci ve stejném commitu.
